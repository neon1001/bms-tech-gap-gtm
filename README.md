# bms-tech-gap-gtm

전기차 BMS(배터리 관리 시스템) 한국 특허로 **GTM 기술맵**을 만들고, 맵의 빈 영역(**기술공백**)을 찾아 그 자리에 어떤 기술이 들어갈지 해석하는 프로젝트의 코드입니다.

**현재: 4단계(GTM 기술맵)까지 완료.** 5단계부터는 예정입니다.

## 한눈에 보기

```
Wisdomain 특허 11,144건 (한국특허+실용, 출원 2011~2020)
   │
   ▼
1. 정제 ── 10,900건 ─┬─► 2. 문장 임베딩 (bge-m3) ──► 4. GTM 기술맵 (30×30)          [완료]
                     │                                   │
                     │                                   ▼
                     │                       5. 공백 후보 탐색 → 6. 가짜 공백 제거   [예정]
                     │                                   │
                     └─► 3. TF-IDF ───────────────────► 7. 역매핑 → 8. 해석         [3 완료 / 7·8 예정]
```

두 갈래로 나뉘는 이유는 역할이 다르기 때문입니다.

- **bge-m3 임베딩**은 맵을 만듭니다. 어떤 특허끼리 가깝고 **어디가 비어 있는지**가 여기서 정해집니다.
- **TF-IDF**는 맵을 만드는 데 쓰지 않습니다. 공백을 찾은 뒤 그 빈 자리가 **무슨 기술인지** 키워드로 읽는 데 씁니다(7단계).

## 단계별 결과

### 1. 정제

- 원본 11,144건에서 **요약이 글자까지 같은 244건**을 지우고 10,900건을 남겼습니다(가장 먼저 출원된 1건만 남김). 94%가 같은 출원인이라 대부분 분할출원으로 보입니다.
- 기업은 '현재소유자' 기준입니다. 현대자동차와 기아는 `현대차그룹`으로 묶었습니다(기아 출원 693건 중 692건이 공동출원).
- 기업별 특허 수 상위: LG에너지솔루션 2,070 · 현대차그룹 1,067 · 삼성SDI 702 · 현대모비스 283 · 삼성전자 276
- 임베딩 입력은 `한국어 제목. 요약`입니다. "본 발명의 일 실시예에 따른" 같은 고정 문구만 지웠습니다.

### 2. 문장 임베딩 (bge-m3)

- 모델 [BAAI/bge-m3](https://huggingface.co/BAAI/bge-m3) (리비전 `5617a9f` 고정), CLS pooling 후 L2 정규화, 1024차원
- 토큰 수 중앙값 198, 최대 1,878 → 입력 한도(8,192) 안이라 **잘린 특허 0건**
- Apple M3 Max 내장 GPU(MPS)에서 4.2분

**점검: 의미가 가까운 특허끼리 실제로 같은 기술 분류(CPC)에 속하는가**

각 특허의 가장 가까운 이웃 10개를 고르고, CPC가 하나라도 겹치는 비율을 셌습니다(Y 섹션 태그 제외).

| 이웃을 고른 방법 | CPC 서브클래스 일치 | CPC 메인그룹 일치 |
| --- | --- | --- |
| 무작위 | 59.4% | 54.8% |
| 글자 2~3-gram TF-IDF (비교용) | 85.9% | 83.6% |
| **bge-m3** | **89.9%** | **88.0%** |

- 무작위 비율이 높은 건 전부 BMS 특허라 공통 CPC(H01M 등)가 많아서입니다.
- 요약이 조금 다른데 벡터가 거의 같은(코사인 0.98 이상) 쌍이 140개 있습니다. 대부분 같은 회사가 같은 날 낸 비슷한 발명(출원인 같음 95%, 출원일 차이 중앙값 0일)이고 내용이 조금씩 달라 별개 특허로 보고 남겼습니다.

### 3. TF-IDF

- Kiwi 형태소 분석으로 일반명사·고유명사·영문만 남기고, 특허 상투어(발명, 상기, 실시예, 장치, 방법 등)를 뺍니다.
- 숫자는 남기지 않습니다. 숫자 토큰은 대부분 "제1"·"제2" 같은 서수에서 나온 잡음이었습니다(빼기 전에는 키워드의 9.8%에 숫자가 들어 있었음).
- 1~2-gram, 5건 미만·70% 초과 단어 제외, 최대 30,000개, sublinear TF, L2 정규화 → **10,900건 × 키워드 17,821개**
- 행 순서가 임베딩·GTM 결과와 같아서 행끼리 바로 대응합니다(7단계 계산에 필요).

### 4. GTM 기술맵

GTM(Generative Topographic Mapping)은 2D 격자를 고차원 공간에 펼쳐 특허 분포에 맞게 휘는 비지도 학습입니다. 학습이 끝나면 모든 특허가 격자의 한 칸(cell)에 놓이고, **특허가 없는 빈 cell도 원래 1024차원 공간의 벡터를 가집니다.** 7단계 역매핑은 이 벡터를 이용합니다.

- 설정: RBF 10×10, 폭 = 중심 간격의 1.0배, 정규화 α = 0.001, PCA 초기화(무작위성 없음 → 같은 설정이면 같은 결과)
- 학습 데이터: 2011~2020 전체 10,900건

**기본 격자 30×30 점검 결과**

| 항목 | 결과 | 비교 기준 |
| --- | --- | --- |
| 학습 | 11.0초, 42회 반복, 로그우도 단조 증가, NaN 없음 | |
| 빈 cell | 67개 (7.4%) | |
| 특허가 있는 cell의 특허 수 | 중앙값 11건, 최대 77건 | |
| 원공간 최근접 이웃 10개가 맵에서 같은·바로 옆 cell에 놓인 비율 | **50.8%** | 무작위 1.1% |
| 같은 cell 안 특허끼리 CPC 서브클래스가 겹치는 비율 | **86.4%** | 무작위 58.7% |

- CPC마다 모이는 영역이 뚜렷하고, 주요 기업마다 특허가 놓인 영역도 다릅니다(`outputs/figures/gtm30_cpc.png`, `gtm30_firms.png`).
- 주의: 맵 **가장자리 cell에 특허가 몰립니다**(가장자리 평균 25.2건 vs 안쪽 10.2건, cell의 13%에 특허의 27%). 분포 바깥쪽 특허가 격자 끝으로 밀리는 것으로 보입니다.

**격자 크기 비교 (4-1)**

격자를 촘촘하게 하면 빈 cell은 늘지만, 데이터가 모자라 **우연히 빈 칸**도 함께 늘어납니다. 안쪽 cell마다 주변 8칸 평균 m으로 우연히 0건일 확률 e^(-m)을 구해(포아송 근사) 더했습니다.

| 격자 | 안쪽 cell 평균 특허 | 안쪽 빈 cell | 우연히 빌 기대 수 | 주변 평균 5건 이상인 빈 cell | 이웃 보존 |
| --- | --- | --- | --- | --- | --- |
| 20×20 | 22.4 | 7 | 0.0 | 7 | 55.4% |
| 25×25 | 14.5 | 13 | 0.1 | 13 | 53.3% |
| **30×30** | 10.2 | 65 | 3.3 | **36** | 50.8% |
| 35×35 | 7.6 | 136 | 26.3 | 27 | 48.4% |
| 40×40 | 5.9 | 233 | 87.4 | 22 | 46.4% |
| 50×50 | 4.0 | 599 | 348.9 | 8 | 41.8% |

30×30에서 믿을 만한 빈 cell(주변이 붐비는 것)이 가장 많고 우연한 빈 칸은 적어서 **기본 격자로 정했습니다.** 20×20, 25×25도 함께 학습해 두었고, 공백이 격자를 바꿔도 유지되는지 확인하는 데 씁니다.

## 설계 결정과 이유

| 결정 | 이유 |
| --- | --- |
| 중복은 **요약이 같은지**로 판단 | 이 데이터에서 출원번호가 겹치는 행은 0건이라 출원번호 기준으로는 아무것도 지워지지 않음. 패밀리 번호는 서로 다른 발명이 묶인 사례가 있어 쓰지 않음 |
| 기업은 **현재소유자** 기준 | LG화학 출원 1,122건 중 999건이 현재 LG에너지솔루션 소유. 출원인 기준이면 같은 회사가 둘로 쪼개짐 |
| 임베딩 모델은 **bge-m3** | 텍스트가 전부 한국어. 원본 제목+요약 기준으로 입력 한도를 넘어 잘리는 비율: ko-sroberta-multitask(128토큰) 80%, multilingual-e5-large(512) 1.4%, bge-m3(8,192) 0% |
| 긴 텍스트를 조각내 평균 내지 않음 | 128토큰 모델로 조각 평균을 내면 원본 11,144건 중 87%가 쪼개지고, 2,839건은 32토큰 미만 자투리 조각이 평균의 50% 비중을 차지함 |
| **맵은 임베딩, 해석은 TF-IDF** (두 벡터를 이어 붙이지 않음) | 이어 붙이면 두 블록의 비중 가중치에 맵 모양이 좌우되고, TF-IDF 차원을 줄이면 키워드를 바로 읽을 수 없음 |
| 학습 기간 2011~2020 **전체** | 맵을 가장 많은 데이터로 만듦. 미래 검증(backtesting)은 2021년 이후 데이터를 따로 받아서 함 |
| 기본 격자 **30×30** | 위 격자 크기 비교 결과 |

## 실행

```bash
pip install -r requirements.txt
python3 src/preprocess.py         # 1. 정제 → data/interim/patents_clean.parquet
python3 src/embed.py              # 2. 임베딩 → data/interim/emb_bge_m3.npy
python3 src/check_embeddings.py   # 2-1. 점검 → data/interim/emb_check.json
python3 src/tfidf.py              # 3. TF-IDF → data/interim/tfidf_matrix.npz
python3 src/gtm_map.py            # 4. GTM 학습·점검 (20·25·30) → data/interim/gtm/
python3 src/plot_gtm_map.py 30    # 4. 점검 그림 → outputs/figures/ (숫자 = 격자 크기, 기본 30)
python3 src/grid_sweep.py         # 4-1. 격자 크기 비교 → data/interim/gtm/grid_sweep.csv
```

- `embed.py`는 처음 실행할 때 bge-m3 가중치(2.27GB)를 내려받습니다. 한 번 받은 뒤에는 `HF_HUB_OFFLINE=1 python3 src/embed.py`로 실행하면 transformers가 다른 형식의 가중치를 추가로 내려받지 않습니다.
- GPU가 없으면 임베딩은 CPU로 돌아가며 더 오래 걸립니다. 나머지 단계는 CPU로 단계마다 몇 초~2분 정도입니다(TF-IDF 20초, GTM 세 격자 약 30초, 격자 크기 비교 약 2분).

## 다음 단계 (예정)

5. **공백 후보 탐색:** 특허가 없는 빈 영역 중 둘레에 특허가 충분한 곳을 공백 후보로 잡습니다. 맵 가장자리는 제외합니다.
6. **가짜 공백 제거:** 원래 1024차원 공간에서 실제 특허가 가까이 있으면 2D로 접으면서 생긴 빈 칸으로 보고 뺍니다. 격자를 25×25·35×35로 바꿔도 남는 공백만 남깁니다.
7. **역매핑:** 공백 cell의 벡터로 그 자리의 기술을 복원합니다. ① TF-IDF 키워드 가중치, ② 임베딩과 가까운 키워드, ③ 둘레 특허의 CPC·대표 특허를 봅니다.
8. **해석:** 공백마다 라벨, 비어 있는 이유(추정), 유형을 정리해 공백 후보 표를 만듭니다. 이 표가 이후 분석의 입력이 됩니다.
